# 两数之和：解法分析

对每个数 `x`，需要找到另一个值 `target - x`。两种解法的区别在于如何查找这个补数。

## 1. 暴力枚举

枚举下标 `i`，再从 `i + 1` 开始枚举 `j`。发现两数之和等于目标值时返回两个下标。

每对不同位置都会被检查一次，因此存在的答案一定能找到；从 `i + 1` 开始保证不重复使用同一位置。

- 时间复杂度：O(n²)。
- 额外空间复杂度：O(1)。

内层循环反复做的是“查找补数”。用哈希表保存已经访问的数值和下标，可以省去这部分重复扫描。

## 2. 一次遍历哈希表

维护“已遍历的值 → 下标”的映射。处理当前值前，先查找补数；若存在，返回已记录的下标和当前下标；否则记录当前值。

以 `nums = [2, 7, 11, 15]`、`target = 9` 为例：

| 当前下标 | 当前值 | 补数 | 查找前的映射 | 处理结果 |
| --- | --- | --- | --- | --- |
| 0 | 2 | 7 | `{}` | 未找到 7，记录 `2 → 0` |
| 1 | 7 | 2 | `{2: 0}` | 找到下标 0，返回 `[0, 1]` |

先查找再插入，表中只包含更早的位置，因此不会重复使用当前下标。处理答案中较后的位置时，另一个位置已经记录，因而能够找到答案；`[3, 3]` 一类重复值也适用。

- 平均时间复杂度：O(n)，按哈希查找平均 O(1) 估算。
- 额外空间复杂度：O(n)。

推荐使用这一解法，以额外空间换取平均线性时间，满足题目的进阶要求。无需排序，也不会修改输入数组。

## 4. 测试与易错点

两种实现共用用例，覆盖原题示例、重复值、负数、零、较后位置的答案和接近数值范围边界的输入。断言检查两个下标有效且不同、对应数之和等于目标值、输入未被修改，不限定返回顺序。

- [Java 测试](../../../java/src/test/java/leetcode/r0001_0050/p0001/TwoSumTest.java)
- [Python 测试](../../../python/tests/r0001_0050/p0001/test_two_sum.py)
- [Go 测试](../../../go/problems/r0001_0050/p0001/solution_test.go)

需要留意三点：

- 返回的是原数组下标，不是两个数值。
- 先查补数再记录当前值。例如 `[3, 2, 4]` 的目标为 6，先记录第一个 3 再查找，就可能错误地返回 `[0, 0]`。
- 下标 0 是有效结果。Java 用 `null`、Python 用 `is not None` 判断查找是否成功，Go 使用 map 查询返回的 `ok`；不能把下标 0 当作未找到。

Java 的 `int` 在本题约束内足够保存两数之和与补数；若将实现复用到更大整数范围，需要重新处理溢出。输入保证有解，代码末尾的异常或 panic 只用于标识不符合该前提的调用。
